# Building a HomeFAX app — the brief every app follows

You are building one of three Next.js 16 apps in this workspace. Read this whole
file, then `docs/ARCHITECTURE.md`, then `packages/db/README.md`, then your app's
spec in `docs/specs/`. Study `apps/contractor/src` — it is the house style.

## Non-negotiables

1. **Next.js 16 is not the Next you remember.** `node_modules/next/dist/docs/` is
   the reference. `cookies()`/`headers()`/`params`/`searchParams` are async.
   Middleware is `proxy.ts`. Page props use the global `PageProps<"/route">` and
   `LayoutProps<"/">` types (generated by `next typegen`/build — run
   `npx next typegen` once before `tsc --noEmit`). `export const dynamic = "force-dynamic"`
   on pages that read cookies.
2. **Every read goes through `@homefax/db` under the signed-in actor.** Use
   `kit.asMe((tx, me) => …)` / `kit.asVisitor(...)`. Row-level security is the
   authorisation; never filter "for safety" in TypeScript instead of relying on
   it, and never call `withService` outside the cases the repo doc comments name
   (sign-in, sign-up, claim codes, invitations, share-link resolution, requests
   for access, the reconstruction pipeline). If you think you need a new
   service-level operation, add a repo function with a doc comment that says why.
3. **Server components + server actions. No client state for forms.** Actions
   take `FormData`, validate with the `str/optStr/bool/num/cents` helpers from
   `@homefax/app-kit`, call a repo, `revalidatePath`, and `redirect`. On failure,
   `fail(path, message)` redirects back with `?error=`; pages render it with
   `<ErrorLine message={sp.error} />` directly under the panel that failed. Wrap
   repo calls in try/catch and pass `errorMessage(e)` to `fail` — it already
   turns RLS refusals into "You do not have permission to do that".
4. **Log every non-owner look at a property.** Property pages call
   `viewProperty(tx, propertyId, actor, { app, path })` from app-kit before
   rendering and 404 (`notFound()`) when it returns null.
5. **Design system = `@homefax/ui`.** `AppHeader` (pass your app's `tabs`),
   `StatStrip`, `GradeChip`/`GradeStamp`, `QualityPanel`, `PartsTable`, `ErrorLine`,
   `LogoMark`/`Wordmark`/`SplashLoader`, and `@homefax/ui/model-viewer` (dynamic
   import, client only). Classes: `.shell .card .sheet .plate .field .rule-grid
   .label .eyebrow .chip .chip-accent .comb .comb-11 .comb-50 .tick .btn
   .btn-primary .btn-secondary .input .tnum .rail`. Tokens: `var(--paper)
   --surface --surface-2 --ink --ink-2 --ink-3 --line --accent --accent-soft
   --accent-ink --grade-a…f`. Add new shared components to `packages/ui` only if
   two apps need them; app-specific ones live in your `src/components`.
   The thesis is "the permit card and the grade stamp": paper register for the
   record, onyx `.plate` for instruments (3D viewer, loaders, sign-in). Mono for
   every figure and label; Space Grotesk for headings. No gradients, no shadows
   beyond `--shadow-card`, no icon libraries (inline 16px SVG strokes only).
   Dark mode works through the tokens — never hard-code a colour.
6. **Copy is design.** Sentence case, plain verbs, specific nouns: "Open the
   record", "Grant ledger access", "Revoke". Errors say what happened and what
   to do. Empty states invite the next action. Never apologise.
7. **Accessibility floor:** labels on every input, `aria-current` on nav, 44px
   tap targets on phone apps, visible focus (already in the tokens), no colour
   as the only carrier of meaning (grades always print the letter).
8. **Charts (admin only)** follow `docs/specs/charts.md`: one axis, thin marks,
   direct labels, status colours reserved, a table view beside every chart.

## Working method

- Run the app with `npm run dev -w @homefax/<app>` (ports: contractor 3000,
  homeowner 3001, admin 3002). The local Postgres is already migrated and seeded
  (`.env.local` is in place). Demo accounts: see `packages/db/src/seed-world.ts`
  — every email ends in `@demo.homefax`, password `homefax-demo-2026`.
- Browser-check your pages with playwright-core driving `/usr/bin/chromium`
  (`--no-sandbox --use-angle=swiftshader --enable-unsafe-swiftshader
  --disable-accelerated-video-decode`). Server actions redirect inside the POST —
  wait on the URL or a selector, never on a GET. Screenshot the key pages at
  390×844 (phone apps) or 1440×900 (admin) and look at them.
- Write a `tests/smoke.test.ts` (node:test + playwright-core) that signs in as a
  demo account and walks the primary flows; it must pass against `next dev`.
- Finish with `npx next typegen && npx tsc --noEmit`, `npm run lint`, `npm run
  build` all clean in your app, and `npm test -w @homefax/<app>` green. Do not
  touch other apps. Changes to `packages/*` are allowed only to add a shared
  component or a repo function; keep them additive and run `npm test -w
  @homefax/db` afterwards.
- Commit nothing. Leave the working tree for review and write a short
  `docs/specs/<app>.DONE.md`: what was built, what was skipped and why, every
  command you ran at the end and its result.

## Shared vocabulary

| Term | Meaning |
|---|---|
| property / house | the physical address; one row, forever |
| record | a contractor's build record on a property (there can be several over a house's life) |
| stage | one of the 11 construction stages; a capture is one filmed stage |
| grade | A–F from the 0–100 stage score |
| ledger | the 50-point checkpoint list (QC-01…QC-50) |
| scope | summary ⊂ ledger ⊂ full — what an outsider may see |
| grant | the owner's permission to an organisation or person |
| share link | a public read-only link at a given scope |
| jurisdiction | a municipality's territory, granting it ledger scope by statute |
| draw | a construction-loan disbursement tied to a stage |
